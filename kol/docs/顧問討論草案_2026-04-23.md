# 專題方向討論草案

**討論對象**：專題顧問教授
**準備日期**：2026-04-23
**作者**：施博瀚

---

## TL;DR

我**沒有換題目**，但我意識到原本想做的「KOL 多因子量化系統」**在資工 CS 含量上不足**，所以調整定位：

> **核心 CS 貢獻從「量化評估」轉移到「中文金融 KOL 結構化資訊抽取 (Information Extraction)」，
> 量化因子表現變成 downstream evaluation，原既定的條件穩健性框架仍保留為應用驗證層。**

時程仍對得上五月中。下方拆細說明轉折。

---

## 一、原本的想法（本次討論前）

### 既定題目（見 `docs/專題提案.md`）

**主題**：基於多情境壓力分析的量化因子穩健性評估

**內容**：
- 用 Alpha101 因子為基礎
- 結合歷史壓力測試 + AI 輔助的假設性情境分析
- 建立因子「條件穩健性」量化評估方法（Taleb-Douady 凸性分析）
- 最終組裝出在熊市仍穩健的策略

### 本次新加入的想法

研究 [banini-tracker (cablate)](https://github.com/cablate/banini-tracker) 後，產生延伸構想：
**「把財經 KOL 言論當 alternative data factor」**

> 比照 Kakade et al. (2023) 對 finfluencer 的 skill ranking 框架，
> 在中文台股圈做首次驗證。

預期 deliverable：
1. 抓取 5-10 個台股 KOL 的歷史貼文 / podcast / YouTube
2. LLM 結構化抽取 → 統一觀點 schema
3. 計算每個 (KOL × subset) 的 skill score
4. 把 KOL sentiment 當 alternative factor，套用我已有的條件穩健性框架

## 二、本次討論的進展與關鍵反思

### 已完成的 infrastructure（4 小時內）

| 階段 | 完成內容 | 數據量 |
|---|---|---|
| 資料工程 | Apify FB scraper + Whisper podcast pipeline + FinMind/yfinance 股價 | 2 KOL × 500 posts + 股癌 RSS 654 集 |
| NLP 抽取 | LLM (Claude) 結構化 → JSON schema | **1685 個觀點** (panzheng 892 + uncle 488 + 8zz 305) |
| 統計分析 | Hit rate / IC / Skill Score / Cross-KOL ranking | 跨 3 KOL × 多 subset |

**初步研究發現（統計顯著）**：

| Finding | n | hit rate | p-value |
|---|---|---|---|
| **panzheng × TW market** 順著做 | 93 | **70.97%** | **6e-5 ★★★** |
| uncle × mid conviction | 233 | 60.1% | 0.0025 ★★ |
| 8zz **不是反指標**，是 lagging follower | 305 | 反向 hit rate 43.9% (p=0.039) | 顛覆市場敘事 |

### 自我反思 — 發現的問題

**關鍵體悟**：上述 4 小時工作中，**真正的「資工 CS novel contribution」幾乎為零**。

| 階段 | 我做的 | 資工 novelty |
|---|---|---|
| 資料工程 | call Apify API | 🔴 commodity tool 套用 |
| NLP 抽取 | call Claude API + prompt engineering | 🔴 **非 CS research** — 沒自己建模型 |
| 因子構造 | pandas groupby + weighted sum | 🔴 應用統計，textbook |
| 條件穩健性 | 二次迴歸（Taleb-Douady） | 🔴 應用計量金融 |
| 研究發現 | binomial test + 描述性結論 | 🟡 是 applied finance finding，非 CS finding |

對比同年級資工專題（BERT 主題分類、Whisper 句子重音、GNN 金融異常等），
我意識到我目前的工作**在「方法論深度」上明顯不足**。

問題不在「方向」，而在「我把 LLM 當成了 commodity，沒有自己建技術」。

## 三、收斂後的新定位

### 重新框架（reframing）

**舊定位**：「我做了一個 KOL 多因子量化系統」 ← 應用 pipeline

**新定位**：

> **「我針對中文金融 KOL 社群建立一套 structured information extraction (IE) 系統，
> 並以量化因子表現作為 downstream evaluation」**

### 新的優先級分配

| 層級 | 比重 | 內容 |
|---|---|---|
| **CS 核心 (60%)** | NLP research | Domain-adapted Chinese financial IE methodology |
| **評估層 (30%)** | 量化驗證 | Factor construction + 條件穩健性 (既有專題的延伸) |
| **工程層 (10%)** | Pipeline | 爬蟲 + 資料管理（輔助、不強調）|

### CS 核心的具體研究問題（候選）

每個都可獨立成 workshop paper 等級題目：

| ID | Research Question | 預期 Contribution |
|---|---|---|
| **Q1** | LLM zero-shot vs fine-tuned BERT 在中文金融觀點抽取的 trade-off | Benchmark + 系統比較 |
| **Q2** | Multi-task joint model：實體 + 動作 + 篤定度共享表示學習 | Domain-specific architecture |
| **Q3** | 弱監督 / Active learning 突破無 labeled data 限制 | Efficient labeling methodology |
| **Q4** | 抽取結果可解釋性：rationale extraction + attention 分析 | Interpretable financial NLP |
| **Q5** | 多模態抽取（FB 貼文常含股票截圖 + 文字） | Vision-language for finance |

**目前傾向 Q1 + Q2**（最 tractable，可同時跑）。

### 新版專題故事 (Pitch)

> 中文金融社群的觀點資料是 underexplored 的 alternative data source。
> 我建立一套針對「個股 / ETF / 動作 / 篤定度」的 IE 系統，
> 比較 LLM zero-shot 與 domain-adapted BERT 的 trade-off (Q1)，
> 並以 multi-task 架構整合多目標抽取 (Q2)。
> 抽取結果作為量化因子，套用我既有的條件穩健性框架，
> 在 panzheng_king 等台股 KOL 上驗證 cross-section skill 異質性。

## 五、想跟教授討論的 decision points

### Q1: 方向確認
**新定位（NLP research as CS core + 量化作 downstream evaluation）對嗎？**
這是我整夜思考後的 best fit，但想確認教授覺得 CS 含量是否足夠。

### Q2: Research Question 選擇
- 走 **Q1 (LLM vs BERT 對比)** ：tractable、風險低、2-3 週可完成
- 還是走 **Q2 (Multi-task joint model)**：更 novel，但 4 週緊
- 還是 **Q1 + Q2 都做**（Q1 在 W2、Q2 在 W3）

### Q3: 標註資料策略
- 我想從現有 1685 筆 LLM 抽取結果**抽樣 300 筆人工複核**作 gold standard
- 是否需要找其他人多人標註計算 inter-annotator agreement？
- 或可以接受我單人標註 + 若干 self-checks？

### Q4: 比較對象的範圍
- 跟哪些 baseline 比？目前想：
  - LLM zero-shot (Claude Haiku 4.5 / GPT-4o-mini)
  - LLM few-shot (5-shot)
  - Fine-tuned BERT-base-Chinese
  - Fine-tuned RoBERTa-zh
- 是否還需要加 traditional NER pipeline (e.g. CKIP / spaCy zh) 當 weak baseline？

### Q5: 條件穩健性框架的角色
- 它仍是我既有專題的核心，但在新定位中變 downstream
- 教授覺得這樣定位合理嗎？或要把它再往 CS 方向推（例如：用 ML 自動偵測 stress regime）？
