# Ultraplan：題目收斂方案

## 一、核心診斷：目前卡在哪裡？

讀完所有資料後，我認為 30 輪辯論雖然產出了大量有價值的分析，但遺留了一個**未解決的根本矛盾**：

> **辯論把 AI 從「核心引擎」降級為「輔助工具」，但沒有回答：降級之後，資工系的技術核心到底是什麼？**

目前 CLAUDE.md 裡的方向——「基於多情境壓力分析的量化因子穩健性評估」——本質上是一個**金融研究題目**，只是用 Python 來實作。凸性分析是統計學、因子回測是金融、壓力測試是風控。教授會問：「這跟財金系的專題有什麼差別？」

以下是我的收斂方案。

---

## 二、確定的題目

### 題目名稱

**「量化因子壓力穩健性的自動化評估框架：從因子實作到策略組裝的端到端系統」**

英文版（報告 / 面試用）：  
*"An Automated Evaluation Framework for Quantitative Factor Robustness Under Stress"*

### 一句話定義

> 設計並實作一套**計算框架**，能自動化地對量化因子進行多層壓力驗證（歷史回測 → Walk-Forward → 壓力情境），產出穩健性評分，並據此組裝出在熊市仍有效的策略。

### 為什麼這個 framing 解決了矛盾

| 受眾 | 怎麼講 | 重點 |
|------|--------|------|
| **教授** | 「我設計了一套自動化評估框架，包含三層驗證架構、穩健性評分演算法、和 AI 輔助的壓力情境生成系統。這是一個計算框架的設計與實證驗證。」 | 系統設計 + 演算法 + 實驗 |
| **優式** | 「大盤下修 20% 時，哪些因子還能獲利？我測了 6 個因子在數百個壓力情境下的表現，找出最穩健的組合。」 | 結果 + 風控思維 |

關鍵差異：**不是在做金融研究，是在建一個「計算工具」來回答金融問題。**  
類比：ImageNet 是 CS 貢獻（評估框架），不是視覺認知研究。同理，這個穩健性評估框架是 CS 貢獻（自動化系統 + 演算法），不是金融研究。

## 三、資工技術核心（回答 ULTRAPLAN 問題 #1）

三個明確的 CS 貢獻點，每個都可以在報告中獨立成章：

### 貢獻 1：端到端自動化評估 Pipeline（系統設計）

```
輸入：因子定義（公式）+ 市場資料
  ↓
[Layer 1] 因子計算引擎 → 自動計算所有因子值
  ↓
[Layer 2] 回測引擎 → 排序→分組→多空，產出基準績效
  ↓
[Layer 3] Walk-Forward 驗證 → 滾動窗口，檢測過擬合
  ↓
[Layer 4] 壓力測試引擎 → 歷史事件 + AI 情境，批次回測
  ↓
[Layer 5] 穩健性評分 → 凸性分析 + 多維指標
  ↓
輸出：因子穩健性排名 + 最終策略 + 視覺化報告
```

**為什麼這是 CS**：這是一個 data pipeline 的設計問題——模組化架構、資料流管理、批次計算優化、結果聚合。Stan 自己設計每個模組的介面、資料格式、錯誤處理。這跟「建一個 ML training pipeline」是同類型的系統工程。

**個人貢獻**：整個 pipeline 的架構設計和 Python 實作都是自己寫的，不依賴外部回測框架（backtrader/zipline），完全掌控每一行邏輯。

### 貢獻 2：穩健性評分演算法（演算法設計）

基於 Taleb & Douady (2013) 的凸性分析，但做了**可操作化的工程設計**：

```python
# 核心演算法：條件穩健性評分
# 對每個因子 α，收集其在 N 個壓力情境下的表現
# σ_i = 情境 i 的壓力強度（市場跌幅）
# R_i = 因子 α 在情境 i 的 Sharpe Ratio

# Step 1: 二次迴歸
R(σ) = a + b·σ + c·σ²

# Step 2: 判斷
# c > 0 → 凸性（反脆弱）
# c ≈ 0 → 線性（穩健）
# c < 0 → 凹性（脆弱）

# Step 3: 綜合評分（多維度）
Score(α) = w1·convexity + w2·survival_rate + w3·worst_case + w4·dispersion
# survival_rate = 壓力情境中 Sharpe > 0 的比例
# worst_case = 所有情境中最差表現
# dispersion = 不同情境下表現的標準差（越低越穩健）
```

**為什麼這是 CS**：這是演算法設計——定義問題、設計解法、實作、驗證。凸性分析的數學概念來自 Taleb，但把它變成一個可計算的多維評分系統，需要設計權重配置、正規化方法、統計顯著性檢驗。

### 貢獻 3：AI 輔助的壓力情境生成系統（AI 應用）

兩層架構：

```
Layer A — LLM 生成宏觀情境（自然語言 → 結構化 JSON）
  輸入：prompt template（情境類型 + 約束條件）
  輸出：{
    "trigger": "半導體禁令升級",
    "affected_sectors": ["Technology"],
    "direction": "down",
    "severity": "high",
    "duration": "medium",
    "recovery": "U-shape"
  }

Layer B — 規則引擎參數化（JSON → 合成時序資料）
  "severity: high" → 跌幅 -20% ~ -30%（均勻分佈抽樣）
  "duration: medium" → 20~40 個交易日
  衝擊曲線：指數衰減 f(t) = A · exp(-λt)
  波動率：基於 GARCH 歷史估計 + 壓力放大係數
```

**為什麼這是 CS**：(1) Structured Output 的 prompt 設計和 schema validation，(2) 規則引擎的映射邏輯和邊界條件處理，(3) 合成時序資料的生成演算法。這是 NLP + 系統設計的交叉應用。

**關鍵定位**：AI 是「情境模板生成器」，不是決策者。核心分析（凸性迴歸、Walk-Forward、策略組裝）全部是傳統計算方法。這樣教授不會質疑「全是 AI 做的」，Chris 也不會覺得「太依賴 AI」。

## 四、技術架構

### 4.1 因子選擇（6 個，全部只需價量資料）

| # | 類型 | 因子 | 金融邏輯 | 實作難度 |
|---|------|------|---------|---------|
| 1 | 動量 | 12-1 月動量 | 過去 12 個月報酬（排除最近 1 月） | 低 |
| 2 | 動量 | 52 週高點比率 | 現價 / 52 週最高價 | 低 |
| 3 | 反轉 | 5 日短期反轉 | 過去 5 日報酬的反向 | 低 |
| 4 | 波動率 | 已實現波動率 | 過去 20 日報酬的標準差 | 低 |
| 5 | 量價 | 量價背離 | 成交量變化 vs 價格變化的不一致 | 中 |
| 6 | Alpha101 | Alpha#6 或 #12 | 從 Alpha101 選一個代表性因子 | 中 |

**為什麼是 6 個不是 8 個**：辯論說 5-8 個，但考慮到 Stan 的量化底子還在建立、且每個因子需要 unit test + 金融邏輯理解 + 壓力測試分析，6 個是最務實的數量。做深比做廣重要。

**為什麼全用價量資料**：避免財報數據的對齊問題（report lag、季報頻率），大幅降低數據工程複雜度。

### 4.2 資料範圍

- **股票宇宙**：S&P 500 成分股（當前成分，接受倖存者偏差，在報告中明確說明）
- **時間範圍**：2006-2025（涵蓋 2008 金融海嘯、2020 COVID、2022 升息）
- **資料源**：yfinance（免費、穩定、日頻 OHLCV）
- **頻率**：日頻計算因子，月頻再平衡

### 4.3 回測方法

- **標準回測**：每月按因子值排序 → 五分位分組 → 做多 Q1 做空 Q5 → 等權重
- **績效指標**：Sharpe Ratio、Sortino Ratio、Max Drawdown、Calmar Ratio、IC（Information Coefficient）
- **Walk-Forward**：70% in-sample / 30% out-of-sample，滾動窗口
- **壓力回測**：在歷史危機 + AI 合成情境上跑同樣的回測邏輯

### 4.4 壓力情境設計

**歷史事件 Baseline（6 個）**：
1. 2008/09-2009/03 金融海嘯
2. 2011/08 歐債危機 + 美國降評
3. 2015/08 中國股災
4. 2018/02 VIX 末日
5. 2020/02-2020/03 COVID 崩盤
6. 2022/01-2022/10 升息熊市

**AI 生成情境（目標 30-50 個有效情境）**：
- 用 Claude API 生成 ~80 個結構化情境
- 規則引擎過濾 + 品質驗證 → 保留 30-50 個
- 每個情境再做 3 個強度變體（輕/中/重）→ 約 100-150 個壓力情境

**為什麼不是 500 個**：辯論中黑臉正確指出，太多情境會導致 LLM 重複 + 品質下降。30-50 個高品質情境 × 3 強度變體 = ~100-150 個，加上 6 個歷史事件，統計上足夠做分位數分析。

## 七、給優式的版本（回答 ULTRAPLAN 問題 #4）

面試時完全不用提「AI 輔助情境生成」和「穩健性評分演算法」這些學術語言。

**面試 Elevator Pitch**：

> 「Chris 叔叔給了一個好問題：大盤下修 20%，怎麼持續獲利？我用 Alpha101 因子做了壓力測試——把 6 個因子放到 2008、2020、2022 等真實熊市環境中跑，發現 [動量/反轉/...] 類因子在熊市反而表現更好。用這些因子組裝的策略，歷史回測 Sharpe X.X，最大回撤控制在 -X%，Walk-Forward 驗證也穩定。」

**策略報告重點**：
1. 策略績效數字（Sharpe、Sortino、MaxDD、年化報酬）
2. 熊市表現（2008/2020/2022 各期的績效）
3. 因子選擇邏輯（為什麼選這些、不選那些）
4. 風控機制（穩健性評分如何幫助選因子）

## 九、為什麼這個方案能 work

1. **範圍可控**：6 個因子、~150 個壓力情境、一個清楚的 pipeline。不是在做一個「系統」，是在做一個「有深度的實驗 + 工具」。
2. **CS 和金融都站得住腳**：對教授是「計算框架設計」，對優式是「策略 + 風控」。不是兩張皮，是同一份工作的不同表達。
3. **個人貢獻清楚**：pipeline 自己寫、演算法自己設計、實驗自己跑。AI 只負責生成情境模板（明確的輔助角色）。
4. **有 Plan B**：最差情況（只跑通歷史回測 + 因子比較）仍然有東西可交、有東西可講。
5. **回應了 Chris 的核心問題**：「大盤下修 20%，如何持續獲利？」— 整個專題就是在系統性地回答這個問題。
