# 量化回測方法總覽

## 一、五種主要回測方式

### 1. 歷史回測（Historical Backtesting）

最基本的方法，直接拿過去真實資料跑策略。

```
2020-01-01 ~ 2024-12-31 的真實股價
→ 套用因子策略 → 算出 Sharpe、報酬率、最大回撤
```

- **優點：** 最直觀，基於真實行情
- **缺點：** 只是 fit 過去，容易過度擬合
- **AI 應用：** 自動跑大量因子組合的歷史回測，人不可能手動試幾千種
- **過擬合風險：** 高（如果只用這一種方法）

---

### 2. 蒙地卡羅模擬（Monte Carlo Simulation）

隨機生成大量可能的價格路徑，測試策略在各種「如果」下的表現。

```
假設股價年報酬 8%、波動率 20%
→ 隨機生成 10,000 條價格路徑
→ 每條路徑都跑一次策略
→ 統計：平均報酬、最差情況、存活率
```

- **優點：** 能測試「還沒發生過的情況」
- **缺點：** 假設分佈通常是常態分佈，但真實市場有肥尾（黑天鵝）
- **AI 應用：** 不用隨機分佈，用 AI 生成「有劇情邏輯」的路徑 ← **本專案的核心創新**

---

### 3. Walk-Forward Analysis（滾動前推測試）

模擬真實使用情境：用過去資料訓練，在「未來」資料上驗證，不斷滾動。

```
第一輪：用 2020 資料訓練 → 在 2021 測試
第二輪：用 2020-2021 訓練 → 在 2022 測試
第三輪：用 2020-2022 訓練 → 在 2023 測試
```

- **優點：** 最接近真實交易情境，能檢測過度擬合
- **缺點：** 計算量大、需要足夠長的歷史資料
- **AI 應用：** 在每個 window 自動選擇最佳因子組合，模擬 adaptive 策略
- **核心價值：** 證明策略不是事後諸葛亮

---

### 4. Cross-Validation（交叉驗證 — 時序版）

跟 ML 的交叉驗證一樣，但時序資料**不能隨機切分**。

```
⚠️ 時序資料必須用「時序分割」，否則就是 data leakage：
  Fold 1: [2020-2021 訓練] → [2022 測試]
  Fold 2: [2020-2022 訓練] → [2023 測試]
  Fold 3: [2020-2023 訓練] → [2024 測試]
```

- **優點：** 多次驗證，結果更穩定
- **缺點：** 每個 fold 的訓練集大小不同
- **AI 應用：** ML-based 因子選擇時必須用此方法，確保沒有未來資料洩漏
- **常見錯誤：** 很多人用標準 k-fold 做時序資料，這是致命錯誤

---

### 5. Bootstrapping（拔靴法）

從真實資料中「有放回地抽樣」重組，生成新的資料集。

```
原始：[日1, 日2, 日3, 日4, 日5]
抽樣1：[日3, 日1, 日5, 日1, 日4]
抽樣2：[日2, 日5, 日5, 日3, 日1]
→ 跑 1000 次，看策略表現的分佈
```

- **優點：** 不需要假設分佈，用的是真實數據
- **缺點：** 打亂了時間順序，破壞了時序依賴性
- **AI 應用：** Block Bootstrap 可以保留局部時序結構，AI 決定最佳 block size
- **進階：** Stationary Bootstrap（隨機 block 長度）解決固定 block 的邊界效應

## 二、方法比較總表

| 方法 | 使用資料 | 能測未來？ | 過擬合防護 | 計算量 | 適合場景 |
|------|---------|----------|----------|-------|---------|
| 歷史回測 | 真實歷史 | ✗ | 低 | 低 | 初步驗證 |
| Monte Carlo | 合成生成 | ✓ | 中 | 中~高 | 極端情境測試 |
| Walk-Forward | 真實歷史（滾動） | 模擬 | 高 | 高 | 策略穩定性驗證 |
| Cross-Validation | 真實歷史（分折） | 模擬 | 高 | 中 | ML 模型選擇 |
| Bootstrapping | 真實歷史（重抽） | 部分 | 中 | 中 | 統計信賴區間 |

---

## 三、本專案的三層驗證架構

```
Layer 1: 歷史回測
  └── 確認因子在真實資料上有效（基準線）

Layer 2: Walk-Forward
  └── 確認因子不是過度擬合（穩定性驗證）

Layer 3: AI-Augmented Monte Carlo ← 核心創新
  └── 確認因子在極端情境下的反脆弱性（前瞻性驗證）
```

三層都通過的因子 → 組成最終策略

## 四、時間序列分析基礎

### Alpha101 中的時序操作

Alpha101 因子本質上就是**時序特徵工程**，常用操作：

| 操作 | 公式 | 白話 |
|------|------|------|
| `delta(x, d)` | x[t] - x[t-d] | 跟 d 天前的差 |
| `ts_rank(x, d)` | rank over past d days | 過去 d 天的排名 |
| `ts_min / ts_max` | min/max over window | 區間最低/最高 |
| `correlation(x, y, d)` | corr over past d days | 過去 d 天的相關性 |
| `decay_linear(x, d)` | 線性衰減加權 | 越近期權重越大 |
| `sum(x, d)` | 累加 | 過去 d 天的總和 |
| `stddev(x, d)` | 標準差 | 過去 d 天的波動 |

### 常見時序模型

| 模型 | 用途 | 白話說明 |
|------|------|---------|
| **MA**（移動平均） | 平滑噪音 | 過去 N 天的平均 |
| **AR**（自迴歸） | 用過去預測未來 | 今天的價格跟前幾天有關 |
| **ARIMA** | AR + 差分 + MA | 處理有趨勢的非穩態資料 |
| **GARCH** | 預測波動率 | 波動率也有慣性（波動叢聚） |
| **Kalman Filter** | 追蹤隱藏狀態 | 從噪音中還原真實趨勢 |

### GARCH 與本專案的關聯

GARCH 模型的核心概念「波動叢聚」（volatility clustering）直接跟壓力測試有關：
- 市場恐慌時波動率會自我強化（VIX 飆升 → 更多恐慌 → 更高波動）
- 在生成合成壓力情境時，需要考慮這個特性
- 否則生成的假情境不夠真實（真實崩盤時波動率不是恆定的）
